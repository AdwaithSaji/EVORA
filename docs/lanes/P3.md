## Build (in order)
0. Hours 2–4: annotate **held-out** queries (`eval/queries_heldout.jsonl`, format in `eval/README.md`) using
   P4's `data_tools/annotate.py`. Don't share them with P2.
1. Re-ID `evora/reid/link.py` — `link_all()`: per track embedding = mean SigLIP of top-3 crops
   (+ OSNet via torchreid for persons if time) + HSV color histogram; candidate pairs only across different cameras with
   0 < Δt < T_max; score = cosine − time penalty; greedy/Hungarian with threshold; write `tracks.global_id`.
   `path(track_id)` → ordered `PathHop`s ("Gate 09:14 → Lobby 09:16 → Rear 09:22").
   Evaluate on the scripted multi-camera walks in the team footage.
2. Alerts: standing queries persisted in `data/memory.db` (table `standing_queries`, create it in your module),
   `check_track` matches new tracks (label/attrs/camera/zone/time window).
3. Live: `evora/live/run.py` replays files at real-time (or RTSP) in chunks → P1's per-chunk ingest → `alerts.check_track`.
4. Privacy: face detection + Gaussian blur for evidence frames and clips (`blur_image`, `blur_clip`).
5. Write-up `docs/writeup.md`: problem, architecture, baseline, contribution, ablation table (from P2), memory design
   (from P4), latency, re-ID results, limitations. ≤ 2 pages.
