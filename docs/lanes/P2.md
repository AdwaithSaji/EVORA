## Build (in order)
1. Baseline `evora/baseline/frame_clip.py`: SigLIP text embedding of the raw query → `frames.faiss` top-k →
   `Hit(camera_id, ts, ts, score, frame_path)`. Use P1's `embed_texts` (or your own SigLIP load until it lands).
2. Eval harness `scripts/run_eval.py`: Hit@1, Hit@5, MRR, camera accuracy, temporal hit (|dt| ≤ 5s or tIoU ≥ 0.3),
   latency p50/p95, per-query-type breakdown, CSV + markdown table in `eval/results/`. Format: `eval/README.md`.
3. Our retriever `evora/retrieval/engine.py` — `search(spec, k, options)`:
   - filters: `spec.camera_ids`, `spec.t_from/t_to`, zone (bbox center in `spec.zone_polygons[cam]`)
   - track search on `tracks.faiss` with prompt ensemble ("a photo of a {x}", "{x}") + color/attribute boost from `Track.colors/attributes`
   - frame search on `frames.faiss` for scene-level queries; fuse with RRF
   - verify top-10 with OWLv2 (`config.VERIFY_MODEL`) on the evidence frame using the full phrase; re-score
   - merge same-camera hits within `config.EVENT_MERGE_GAP_S` into one event
   - attach `clip_path` via `evora.ingest.cut_clip`
4. Ablation flags (`options`): `use_filters, use_tracks, use_frames, use_verify, use_merge` → `run_eval.py --no-verify` etc.
   Produce the ablation table for the write-up.
5. Latency: keep models warm, cache text embeddings, verify only top-K. Report vs baseline.
