## Then: chat + memory
1. `evora/memory/store.py`: SQLite at `config.MEMORY_DB`, table `aliases(alias_norm PK, camera_id, polygon_json,
   created_at, source_utterance)`. Commit on every `learn()`. Same API as `mock.py`; switch `__init__.py`.
   Resolution: exact → fuzzy (rapidfuzz ≥ 92) → camera names → None. Mid-confidence match = ask
   "Is 'front gate' the same as 'main gate'?" (answer stored as a new alias → still ask-once).
2. `evora/chat/parser.py`: Ollama (`config.LLM_MODEL`, JSON format) → QuerySpec fields (object, attributes,
   location phrases, relative time → absolute via `index.reference_now`, action, want_path). Regex fallback = current mock.
   Only location/zone phrases can become `unresolved`; object words go to open-vocab search.
3. `tests/test_memory_restart.py`: learn in one subprocess, ask in a fresh subprocess → no clarify.
4. `app/main.py`: camera thumbnail grid for clarification, optional region drawing (streamlit-drawable-canvas),
   evidence frame with bbox, clip, path timeline (P3), Memory sidebar, baseline-vs-ours toggle.
